# コメント規約 (mirs)

AI・第三者が文脈なしで読めることを目的とする。対象は `src/*.cpp`、`scripts/*.py`、`launch/*.py`、`config/**/*.yaml`。

## 1. timeless原則

- コード内コメントに来歴・議論の経緯を書かない（例：「旧〜」「現行」「当面」）。
- 来歴はコミット文・PRに書く。コードには現在の仕様だけ残す。
- 数値の根拠は式・単位で書く。人名・日付・バージョンを書かない（派生ファイルの日付管理は除く）。

## 2. Doxygen軽量形

- 対象：`src/*.cpp` のファイル・クラス・公開関数、`scripts/*.py` のモジュール・クラス。
- 必須は `@file`/`@brief`、`@param`、`@return` のみ。`@author` `@date` `@version` は使わない。
- C++は `/** */`、Pythonはdocstringで書く。

```cpp
/** @file parameter_publisher.cpp
 *  @brief /params でESP用パラメータを定期転送するノード。
 */
```

```python
"""走行軌跡を /traveled_path に配信するノード。"""
```

## 3. 通常コメント

- 書くのは意図・単位・契約の3点：なぜこうするか、単位、前提条件。
- 物理量・周期・QoSには必ず単位・値を付ける（例：`[m/s]`、`500ms`、`depth 10`）。
- launchの条件分岐には「いつ有効か」を1行で書く。

## 4. 禁止事項

- コメントアウトされたコードの放置（不要なら削除し、復元はgitに任せる）。
- 自明な内容の繰返し（コードの朗読）。
- 対話・チャットの文脈を前提にした表現（例：「さっきの」「あの問題」）。

## 5. API文書の生成

```bash
doxygen Doxyfile
```

- 出力は `docs/generated/`（HTML＋XML）。git管理外。静的配置のみで動き、サーバ不要。
- 警告ゼロを維持する（`WARN_AS_ERROR=YES`）。公開API追加時は文書コメントを付けてからコミットする。
